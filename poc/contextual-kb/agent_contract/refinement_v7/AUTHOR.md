## Rubric interpretation

`applies_to` names requested aspects, not required output question indices. An evaluator maps these names to the actual question clauses. Every requested aspect must be covered, with the appropriate conditions independently preserved in its question and assigned through the ledger. A legitimate compound formulation must preserve the same distinctions and local attachments. Neither exact question counts nor minimum ledger counts are grading requirements.

The listed excerpts are meaningful source evidence, not a mandated unique segmentation. Equivalent meaningful verbatim excerpts are acceptable when their complete meaning applies to each assigned question and appears in both source and bound question. Larger excerpts must not import local restrictions into unrelated operations. Harmless grounded redundant context is acceptable unless it changes meaning, scope, or stage. An event being observed is still a condition. Mere API names, custom names, and requested targets do not by themselves require ledger entries.

Scope strings preserve stated uncertainty; equivalent faithful representations of uncertain versions are acceptable. Heterogeneous version/adapter comparisons require null global scope with the pairing preserved in question text. Retracted scope is inactive. Core-only scope uses adapter `none`.

The batches cover transition observations, settings and dependencies shared across aspects, unrestricted versus restricted support checks, nested support gates, stage-specific registration/use, completed setup, callback targets versus restrictions, local and shared exclusions, cross-field attachment, return transitions, value pairings, corrections, uncertain and heterogeneous scope, quoted claims, possible nonexistent identifiers, and no-condition/empty controls.

Validated JSON parsing, unique sequential IDs F01–F24, batches 1–3 with eight cases each, one matching rubric per case, exact source occurrence of every reference excerpt, and resolution of every `applies_to` label to an authored aspect. Reviewed local/shared attachment and stage semantics. These checks validate authored data consistency, not candidate performance or Formly API behavior.
