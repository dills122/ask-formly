# Candidate retrieval and relevance selection experiment

Isolated four-arm development comparison: frozen foundation, depth20 rank merge, native relevance selection over depth8 candidates, and native relevance selection over depth20 plus original candidates. Protocol and selector prompt are fixed before inference. Existing candidates, models and data/DB remain immutable; sealed evaluation is never semantically read.

Read PROTOCOL.md for criteria and AUTHOR-EXPLANATION.md for implementation. Test with:

    python3 -B -m unittest discover -s poc/contextual-kb/agent_contract/relevance_selection_v1 -p 'test_*.py'

Acquisition uses the POC .venv Python and local copied offline embedding cache. pipeline.py acquire and score use exclusive first-save outputs and must not be rerun into existing output paths. Native foundation/selector artifacts are first submissions, not regenerated by test execution. Results are diagnostic native-agent feasibility, not deployed-model qualification or final answers.
