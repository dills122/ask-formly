# Dependency evidence and recovery follow-up

**2026-10-28 — guidance-only change; facts and installed DB unchanged.** The
[fresh composition audit](caller-composition-audit.md) found useful bounded
answers, so this follow-up targets specific recovery decisions rather than
rewriting answer composition or ranking. Recipe storage remains deferred.

## Changes

Both caller guides and live help now ask callers to identify the owner of a
missing claim: Formly, a versioned dependency, or application code. Fetch relevant
already-listed candidates when their complete records can settle the decision,
and seek the missing mechanism rather than a whole application recipe.

Dependency ownership does not suppress relevant Formly integration evidence. For
remaining dependency-only behavior, the caller should identify the actual
installed version and consult matching primary sources using its available,
authorized tools. It must not infer Angular versions from Formly or substitute
latest docs. When access/version is unavailable, state the precise handoff. For
custom code, request the missing implementation and runtime observations. Keep
useful supported advice and labeled application proposals; handoff does not
prove corpus exhaustion. No hard call cap or overlap threshold was added.

Source runtime is now `formly-model-free-discovery-15+c385659c07a7`, still pinning
the existing 192-fact DB. The comparison baseline is guidance14
`formly-model-free-discovery-14+2ca5c504bc81`. No retrieval/ranking algorithm, fact,
compiler/schema, model or installed DB was changed.

The [dependency evidence guide](dependency-evidence.md) supplies inspected
Angular 13.3.11 source for group validation propagation and disabled-value
aggregation, with conditions and version limits. It distinguishes a group
validator from sibling leaf validators, event suppression from validation,
and registered control values from Formly model data. The guide is not admitted
DB knowledge and does not qualify a consumer running a different Angular version.
The MCP does not acquire a web tool or dependency index; external evidence access
remains the calling agent's responsibility.

after topic help is legitimate. New IDs and overlap counts alone are insufficient
to decide whether a discovery call was useful.

## Frozen fresh comparison

An independent generator wrote four new questions without facts, prior results
or library tools. They cover dependency serialization with explicit Angular
16.2.12, reuse with an unknown Angular version, an unknown scanner widget, and
ordinary configuration preservation. Both guidance arms receive identical
question-only prompts against the same 192-fact knowledge snapshot. Cases,
request-derived decisions, grading criteria, budgets and runtime identities are
frozen before execution. Each arm gets one independent generation per question.

The harness permits ask-formly calls only. It measures evidence-owner routing,
correct handoff, retained answer quality and recovery cost; it cannot demonstrate
completion of an external documentation lookup. The Angular 13.3.11 guide is not
supplied to callers and must not be substituted for the explicit 16.2.12 request.
No quality retries are permitted. These are fresh development cases, not sealed
evaluation or a statistical causal estimate.

## Paired execution results

All eight sessions completed within budget, with no launch failures or observed
tool-boundary violations. Baseline D03 hit one oversized fact-fetch rejection;
it is retained as one failed call, even though two diagnostic entries describe
it. No quality reruns occurred.

| Metric | Baseline14 | Guidance15 |
| --- | ---: | ---: |
| Non-help calls | 26 | 27 |
| Help calls | 6 | 6 |
| Discovery calls | 13 | 11 |
| Repeated candidate occurrences across discovery calls | 15 | 8 |
| Already-delivered full facts fetched again | 0 | 0 |
| Reserialized response-envelope bytes | 414,633 | 390,206 |

Independent review found four bounded complete answers per arm, addressing all
21 required decisions in each arm. No supported composition was lost, no
unsupported Angular-version substitution or custom-widget guarantee was found,
and no premature cutoff issue was identified. Correct handoffs count as bounded
answers; these scores do not mean external evidence or application execution was
obtained. Review also retained a minor baseline D01 provenance limitation: an ancillary
reset-on-hide-default aside relied on a discovery claim without fetching its
complete record; no required decision depended on it.
Both arms already handled many boundaries correctly, so the result does
not establish that the change was necessary for those answers.

The result is mixed: discovery calls and response bytes decrease (bytes about
5.9%), but total non-help calls increase by one. D01/D02/D03 non-help counts are
unchanged; D04 increases from six to seven and its response bytes rise. Do not
claim an overall speedup, fewer tool calls or token/billing savings. There is one
generation per arm, so causal attribution and stability remain unestablished.
The earlier hypothetical C02/C03/C08 savings are not these measured results.
