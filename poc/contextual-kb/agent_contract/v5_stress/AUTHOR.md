## Rubric interpretation

`aspects` are semantic coverage labels, not a required number or ordering of generated questions. Separately searchable operations/outcomes must remain identifiable; explicit comparisons keep their alternatives paired. A legitimate compound question is acceptable when it preserves the intended distinction and gate attachment. The evaluator must not manufacture a failure from alternative phrasing or excerpt segmentation.

Each `mandatory_conditions` item describes a required active relationship and the aspects to which it applies. `excerpt_examples` are illustrative exact source fragments, not unique gold spans or a demand to use every example. An equally meaningful verbatim fragment is acceptable. When the meaning includes multiple pieces (such as both version and adapter), all those pieces remain required even if an implementation splits them across bindings. A longer source excerpt can cover several conditions if it stays correctly attached. The exact excerpt chosen must occur in the question and corresponding binding under the frozen ledger policy; text-only preservation is insufficient for required conditions.

`optional_history` explicitly records interchangeable same-subject history representations. `forbidden_attachments` identifies cross-subject/local-scope leakage, retracted conditions, unsupported expansions, or factual presuppositions to reject. These entries are semantic restrictions, not forbidden token lists: a question may mention a retracted name to explain that it has been replaced without treating it as active. Likewise a negated contrast must not be mistaken for an affirmative restriction. `scope` gives expected global version/adapter values; case-specific scopes still need to appear in each applicable question and binding. Bare names, output nouns, operations, and exact registration targets are retained in text but do not automatically require extra ledger entries.

The rubric covers useful question meanings separately from binding compliance. It does not claim API existence, Formly answer accuracy, retrieval coverage, or production qualification. Supplied API names—including deliberately uncertain names—are data for neutral questions.
