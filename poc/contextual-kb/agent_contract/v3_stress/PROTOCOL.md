# Frozen v3 repeated development stress test

24 independently authored fresh realistic requests, three batches of eight, each repeated three times in fresh agent contexts (72 response slots). Author sees v2 scope only, not v3 or prior cases. Parent checks rubric ambiguity before input freeze. Generation gets frozen v3 CONTRACT.md and only assigned request packet. No gold rubric, history, other outputs, tools for answering, or selected retries. A batch shares context; repeats are fresh. Native inherited agent model is actual generation but provider revision, temperature and random seed are uncontrolled. This is not a controlled production API latency/determinism test.

Freeze candidate and all existing protected artifacts. New artifacts only in this directory. Keep sealed evaluation contents unread; preservation hashes only. No training, source edits, DB, retrieval or answer tests. v3 stays unchanged even if a failure occurs.

Every output is retained before validation. Count all72 slots, including missing or invalid outputs. Score structural validity separately from independent semantic assessment of requested-aspect coverage, shared/local conditions and polarity, exact API/value pairings, scope, justified library questions, standalone usefulness, and binding completeness/attachment. Equivalent question wording and legitimate decomposition are accepted; arbitrary exact question counts are not gold.

Report per-batch and per-case results, all-three-success cases, exact canonical-JSON equality separately from semantic consistency. Canonical equality sorts object keys only; question/binding order and words remain significant. Semantic stability is independently graded and is not inferred from three passing structures or equal counts. A repeated identical mistake is stable but fails usefulness. Three runs of24 cases are correlated observations, not72 independent requests. No superiority claim vs v2: no new v2 arm.

Decision gate: all24 requests usable in all3 runs with no material omission, scope leakage, invented requirement or condition/binding loss. Any failure prevents an unqualified stability claim; report concrete failures and frequency without tuning. Development evidence only, no sealed qualification or final-answer accuracy claim. Review all72 outputs independently and audit harness/frozen evidence; maximum3 independent review instances only if material harness fixes warrant another, never to replace an unfavorable verdict.

Generation delivery: each isolated agent reads one packet containing the full contract and eight requests, then writes one JSON array of {id,output} records. File I/O is solely test transport; no lookup or execution is allowed to derive answers. A malformed/missing batch is retained as a batch error and all affected slots fail; no regeneration. The exact bytes of raw batch files are frozen before semantic grading. Transport envelope is not part of the individual v3 schema. Native agents follow an instruction packet rather than a pinned production system-message/API deployment; orchestration overhead is not planning latency.
