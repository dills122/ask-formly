# Integrated advisory Formly lookup

Use the frozen qualification_v3 foundation contract and retained role_boundary_adaptation epoch6 GLiNER adapters. Caller supplies original request and the foundation's structured question_plan. This module validates and projects that plan; it does not silently replace the native reasoning step with a mechanical planner or claim to host an LLM.

For each derived question, GLiNER extracts six described roles at threshold0.5 with native flat decoding, CPUfloat32/fourthreads, frozen base and adapter. Reuse the tested gliner_integration_v1 integration boundary. Return advisory role_hints, diagnostics, raw extractions and timings alongside the authoritative unchanged question_plan/search_requests.

Retrieval receives ONLY full-question search_requests. Call the unchanged retrieval_integration_v1 bridge with enhanced=False, preserving original hybrid depth8 and merge_obligations cap8. Hints cannot filter, rewrite, add queries, change ranking, remove candidates or determine answerability. Return original candidate records separately from annotations, marked candidate_only. No answer generation, application investigation, DB edits, training, model edits or sealed evaluation access.

Runtime defaults to adapter1701 solely as a stable administrative choice; --seed1702 runs the equally retained alternate. This is not seed selection based on scores and not an ensemble. Both are exercised in integration verification. Model loading or inference failure yields explicit degraded advisory status, while full-question retrieval continues. Invalid foundation input fails before model loading or retrieval. Actual retrieval failures propagate rather than masquerade as success. Empty question plans execute neither retrieval nor extraction.

Acceptance: correct exact query strings/order/counts and final fact IDs equal foundation-only for every test input with BOTH models; no core/input mutation; useful structured hints actually emitted for explicit API cases; all hints advisory-only; model/DB byte and parameter identity preserved. Inject loader/inference exceptions, malformed spans, unknown roles and overlaps and prove queries/results survive. No extraction accuracy improvement or final-answer accuracy is claimed by these functional tests.

Write only this directory. Preserve existing candidates/DB/model files and all prior evidence. Validation uses36 saved realistic plans plus12 fresh first-generation requests. Record first outputs and errors, never repair cases to pass. Independent completed review covers code and actual evidence; maximum3review instances for this integration flow. No fresh gold annotation/training loop or replacement qualification gate.
