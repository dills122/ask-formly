Status: completed independent review. The frozen continuation criterion passes; qualification fails. Continued bounded research is supported; integration is not.

## Harness assessment

`data.py` validates exact source-grounded envelopes, rejects unclear training labels, exports explicit offsets and every role including empty lists, and rejects duplicate training questions/IDs. `train.py` verifies native InputExample roundtrips and exact native token-target mappings for every training and development row before inference or optimization. The retained `transport.json` reports all 62 training and 24 development rows exact.

Inference receives only question strings and the fixed six-role description schema. Development labels enter the transport qualification and later scoring, not optimization. The training loop precomputes batches only from training examples, uses fixed epochs/seeds, averages each eight-example accumulation group, and correctly averages the last six-example group by six. Explicit finite loss/gradient checks precede updates. The installed trainer freezes base parameters before applying the requested architecture-aware LoRA targets.

Save verification first saves an adapter, then loads that saved adapter on a fresh base; it checks prediction equality and all named parameter hashes. Random states are restored after fresh loading, which otherwise seeds Torch. The next epoch explicitly restores training mode. Final verification requires adapter changes with no frozen-parameter changes. Failures abort rather than become successful quality observations. The eight-row reload panel is a deterministic equivalence check, not a generalization metric.

The initial harness unnecessarily hashed old adaptation compatibility modules; the author removed those references before running and expanded the freeze to actual base files and installed GLiNER source. Package versions are retained. The run therefore uses the local pinned base, not an older adapted checkpoint. Full end-of-run hash consistency and save receipts still require review after completion.

## Limits that remain even if scores improve

The development set has only 24 synthetic questions, including four negatives and four model-key mentions. Reserved names differ but semantic templates overlap. The two seeds are repeated optimization of this same dataset, not independent samples or confidence intervals. This experiment tests clear inputs; it cannot qualify ambiguity detection, unseen application questions, retrieval, or answer quality. The frozen continuation and qualification gates must be reported separately, and weak results must not cause checkpoint/threshold selection or decoder repairs.

## Assessment review before final predictions

The eight data/assessment unit tests pass. The continuation decision implements the protocol: exactly two trained candidates, each improving raw dev F1 by at least 0.10 and accepted F1 strictly, without a greater-than-0.05 drop in any nonempty role's recall. Small numerical tolerances preserve the intended inclusive threshold.

The reused scorer deliberately counts individually source-valid raw spans even when overlaps invalidate the complete accepted envelope; the accepted arm then loses all spans from that envelope. It counts these cases as invalid, so they cannot pass qualification. This separation is faithful to the frozen raw/accepted distinction. `score.evaluate` calls the legacy `contract.score_case`, not `hardened.score_case`; their relevant behavior is equivalent for the dictionary rows generated by this harness. Missing/malformed rows are not a reason to count a successful envelope.

The automated qualification decision requires 90% precision/recall overall and in every role, no invalid envelopes, and complete compound-API/quoted-span recovery. Its special-boundary predicates do not include unquoted opaque expressions. Therefore the boolean alone cannot certify the protocol's additional requirement of no unresolved critical boundary misses: the final review must explicitly inspect the opaque expression in V12 (and any other material remaining miss), or add an explicit diagnostic before final predictions. This affects qualification interpretation, not the continuation gate or training configuration.

The seed-1701 epoch-1 save receipt reports exact predictions and named parameters after loading the saved adapter. Final receipts and end-of-run source consistency were subsequently verified below.

## Complete remaining development errors

- Both seeds, V20: omit all three quoted value occurrences `"Waiting"`, at [24,33), [64,73), and [111,120). All three property APIs remain correct. Value recall is consequently 9/12 = 75%, below the qualification floor. These are unresolved required literal-boundary/content misses, even though overall recall exceeds 90%.
- Seed 1702, V07: emits an extra `registration_name` for the first `'memberToken'` at [31,44), where it also emits the correct `model_key`. The second occurrence is correctly a registration name. This cross-role overlap invalidates the whole envelope, costing both correct mentions in accepted scoring. Registration-name precision is 5/6 = 83.33%, below the qualification floor.
- Seed 1702, V24: emits `value` for `hidden fields retain their answers` at [25,59), a behavioral claim explicitly excluded by the contract. This is the one false-positive negative question for seed 1702; seed 1701 has none among the four clear negatives.

There are no other development false positives, false negatives, or invalid envelopes in either trained seed. Explicitly inspected V12: both seeds extract the complete `(field) => field.model.memberToken === null` value at [64,107) and the complete `expressions["props.disabled"]` API at [113,142), with no nested fragments, extras, or conflicts. The opaque-expression check therefore passes despite its absence from the generic automated boundary predicates.

## Final verdict

The bounded experiment is valid evidence that supervision can improve this six-role extraction task on these 24 synthetic development questions. Both seeds satisfy the predeclared continuation criterion. They fail the predeclared qualification standard: both have only 75% value recall and unresolved quoted-value misses, while seed 1702 additionally has an overlap conflict and insufficient registration precision. `qualified=false` is correct. Do not integrate either checkpoint or claim readiness.

Further investigation is justified, with this development set now exposed and unsuitable as an untouched future test. Any next qualification needs separately authored unseen questions and should retain repeated literal content, occurrence-role contrasts and quoted behavioral negatives. This recommendation does not authorize a new run or change the completed protocol. The result establishes neither ambiguity detection nor robustness on natural agent-generated questions, and does not measure retrieval or answer quality. No critical harness-integrity issue remains unresolved; the semantic failures above remain visible and unfixed.
