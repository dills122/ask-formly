# Project indexing implementation

Authorized 2026-10-15: build ask-formly indexing, discover conventional setup, ask targeted questions where needed, and retain project context under `.agents/ask-formly/` in the consuming repository.

Delivered a Python standard-library helper, an optional TypeScript compiler-API analyzer and a skill workflow. Output is a candidate static inventory/connection map, not Angular compilation or runtime proof. The agent follows registrations/helpers and records short source-backed notes. No project code, factories, package scripts or network calls execute during indexing. See [qualification and example](qualification/project-index/README.md).

Commands: scan (create/refresh), check (read-only freshness), find (bounded lookup), trace (bounded connections), note (record reviewed context with source references). Output: config.json, index.json, index.md, graph.json and notes/<id>.md/.json. Scan preserves notes. Check notices additions, deletions, content edits even with unchanged timestamps, settings/tool drift, incomplete reads and edited notes/artifacts. In v1 every scoped source change marks existing notes for review; this conservative boundary avoids false freshness from incomplete dependency tracing. Preview truncation and unparsed metadata remain explicit discovery warnings, separate from input-read completeness.

Discovery: conventional Angular/Nx/package/tsconfig/Playwright metadata; TypeScript/HTML/JSON signals for Formly hosts, registration, fields, expressions, custom types, wrappers and arrays. Relative import/template links are candidates; path aliases and dynamic construction require agent tracing. Requested version ranges and npm-lock versions are separately labeled; unsupported lock formats stay unknown. Git ignores respected where Git metadata is available; explicit scope/exclude settings, default dependency/build/agent-folder exclusions, file-size limits and symlink skipping are reported. Incomplete reads never receive a clean freshness claim.

The agent asks only unresolved, consequential questions: which app in a monorepo, external configuration/shared libraries, or E2E environment/fixtures when not inferable. It persists answers with provenance and produces useful partial context if optional answers are unavailable. It does not ask the user to explain facts the code already establishes.

Tests before implementation: discovery and no execution/raw-source copying; scope/ignore behavior; source and settings freshness; notes survive refresh and remain stale until reviewed; paths/symlinks/unmanaged output protection; partial scans; monorepo versions and unresolved imports; bounded query; synthetic 500-file fixture. All development fixtures/results stay outside portable skill. Stop after CLI behavior, skill workflow and realistic local exercise pass. No workplace integration or E2E performance claim without consuming-project evidence.

## Clarification incorporated before implementation

Owner explicitly wants a full inventory and connection map: main Formly entry points; custom fields/wrappers/validators mapped to files; observed naming/location patterns; UI hosts and config initialization; sub-config/helper/component relationships. Add graph.json plus a scoped trace command. A TypeScript AST pass, when the project's TypeScript compiler is available, records declarations, registrations, field-type/validator references, configuration dependencies and UI host bindings. Keep lexical discovery as an explicitly weaker fallback, and retain unresolved dynamic/alias/scope cases. Registration candidates must remain scope-qualified; duplicate names must not be collapsed into a fictitious global winner. Browser/runtime connections stay unverified until observed. The scanner never executes application configs.
