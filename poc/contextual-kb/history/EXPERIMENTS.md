# Question layer and MCP experiment history

This is historical context, not a menu of supported implementations. The current entry point is [the accepted MCP foundation](../mcp_foundation/README.md). Results below describe different panels and denominators; they must not be combined into one accuracy number.

## What we tried and learned

| Stage | Approach and result | Decision carried forward |
| --- | --- | --- |
| Hand-built question probes | Regex/stopwords, word pairs and literal subquestions failed to preserve enough intent. Wider retrieval helped fact coverage but could not repair absent knowledge or answer omissions. | Separate question understanding, retrieval, evidence selection and answering. Do not call a query rewrite a new architecture. |
| Library-based A/B | A used spaCy dependency projection; B used LlamaIndex question generation with local Qwen. Complete first plans:17/30 versus 18/30; critical-error cases:1 versus 2. A was much faster (3.94 ms median versus 1.480 s). Neither met 27/30. | Keep A as historical speed/reference evidence; neither became the accepted planner. Deterministic output was not sufficient correctness. |
| GLiNER decomposition/record adaptation | Feasibility, annotation pilots, anchor/record identity compatibility, first-save verification and training showed that open-ended application requests were not a sound direct extraction target. | The caller/planner must derive library questions first. The KB does not know custom application components. |
| Library-question agent contracts | Progressed through shared conditions, ledger completeness, event timing, independent follow-ups, exclusions, exact source copying and JSON delivery. qualification_v3 recorded 144/144 fresh outputs (48 requests×3), plus 18 diagnostics, usable under its fixed rubric. Only 2/48 had exact JSON equality. | Meaning/condition preservation matters more than byte-identical generations. Frozen qualification_v3 is the accepted planner, with disclosed later exact-wording limitation. |
| Focused GLiNER extraction | Bare/described labels, boundary/role contrasts and native flat decoding improved six-role API/name/value extraction. Retained role/boundary epoch 6 adapters scored 35/40 and 36/40 exact fresh envelopes; typed-span F1 97.14%/98.10%. Remaining cross-role/ordinary-word mistakes failed strict replacement gates. | Retain both seeds 1701/1702 as advisory extractors. Flat decoding is not global cross-role exclusion. Neither score proves question or final-answer accuracy. |
| Attributes, retention and distillation | Native span attributes, malformed-span rejection, continuation-only controls and frozen-teacher distillation were actually trained/tested. Improvements traded against old behavior; matched distillation did not reliably beat continuation. | Do not promote later training just because a local metric improves. Keep stronger frozen extractors and disclose forgetting/retention losses. |
| Verifier and entailment branches | Exact-span verifier compatibility/training/calibration and ambiguity audits found role disagreements that would damage correct mentions. A 30-question shadow panel had 28/30 and 29/30 correct baseline mentions, but four correct mentions per seed received wrong verifier roles, with no successful wrong-role repair. Entailment did not justify adoption. | No learned verifier, entailment stage or spaCy sidecar in the accepted setup. |
| Advisory integration | Foundation-only and each frozen GLiNER arm preserved 174/174 core plans/search requests. On a 44-row annotation panel precision was 89.53%/90.59%, recall 88.51% for both; annotation errors remained. | GLiNER adds useful advisory spans and diagnostics, never retrieval filters or replacements for full questions. Preserve model identity and graceful availability behavior. |
| Supplemental queries and eight-slot policies | Context-preserving supplemental queries raised pooled recall 89.39%→89.94% on one panel but lost useful facts. Protected-six merging also lost relevant facts. Wider candidate retrieval and sparse semantic selection improved minimum-group coverage while discarding corroborating evidence. | Reject aggregate-only wins and seed/panel cherry-picking. Keep original full-query retrieval and explicitly check losses as well as gains. |
| Initial real MCP and diagnosis | The real calling agent exposed partial and missing support. A stored expression-callback fact was excluded by channel depth/eight-slot selection; exact required/validator recipes were also absent from the DB. | Distinguish retrieval misses from missing knowledge and caller mistakes before changing a layer. |
| Bounded selection repair | Deeper candidates retain the full original questions and baseline packet. A hosted selector may replace at most 2 irrelevant slots. Three saved callback misses recovered;81 valid slots lost no labeled relevant facts/groups. One fresh foundation output failed the exact-copy rule, so the original overall gate stayed failed. | Retain the failure; do not relabel conditional retrieval success as a full qualification pass. |
| Bounded wording fix | `props.disabled be configured to track model.isLocked` preserved meaning but broke the ledger substring. A whole-question grammatical rewrite restores strict compatibility. Changed paths, negation, dependencies and missing bound conditions still reject.81 prior valid plans stayed unchanged; three repeats of one saved output were repaired. | Small audited grammar support, not arbitrary fuzzy equivalence. Raw output/rewrites retained. |
| Hosted integration and usability | Ten actual hosted selections and eight real MCP calls passed the hosted check. Both live expression cases gained callback context; missing recipes remained explicit. Stable-launcher check passed 27 tests, restart/error checks and eight more real-agent calls across both frozen models. | Accepted local stdio foundation. Existing-checkout usability established; whole-library accuracy, fresh-machine portability and production scale are not. |

## Process that made results interpretable

We froze contracts, criteria, inputs and first responses; used TDD for logic; ran both retained seeds; kept exposed development panels separate from sealed evaluation; checked parameter/DB hashes; and used fresh-context independent reviews at bounded decision points. Repeated outputs are correlated, not additional independent questions. Annotation correctness, plan usability, retrieval recall, minimum supported-group coverage and final-answer completeness are different measures.

Negative results and operational failures remain part of the history. No gate was retroactively relaxed to turn a failure into a pass. Some test launches were approval-blocked before execution; safer cases or explicitly authorized runs were recorded separately. The exact-wording failure was an operational contract failure, not evidence of lost meaning.

## Current composition

Frozen agent contract -> bounded wording adapter -> frozen GLiNER advisory spans -> original full-question hybrid retrieval -> bounded hosted eight-slot selection -> stored facts/citations -> calling agent. Base knowledge remains 46 authored facts in 9 documents for Formly 6.3.12/core/Material. Exact required/validator recipes remain known gaps.

The Git checkpoint retains active code, setup, tests, compact results and this history. Local recovery archives preserve superseded sources/raw artifacts; large environment caches and obsolete experimental trees are excluded from the deliverable. Sealed evaluation stays local and unopened. See [packaging and recovery](../packaging/README.md) for what Git does and does not back up.
