# Frozen retrieval and consistency protocol

This is a new query-bridge experiment, not an edit to the frozen integration candidate. Keep qualification_v3 foundation, both GLiNER epoch6models, labels/threshold0.5/flatdecoding and existing PilotIndex engine unchanged. All work inside this new directory. Existing data/DB locked; SQLite mode=ro plus query_only, no stored-vector/index updates. Existing PilotIndex constructs its ordinary transient in-memory vectors from the unchanged46facts; no compilation, seeding or persistent index build. Source: https://www.sqlite.org/uri.html (mode=ro).

Inputs:36fresh development requests in3fixed batches of12, selected before outputs.10catalog-related requests and2unsupported requests perbatch. Run foundation once perbatch firstsubmission; no repair/retry. All3arms consume same foundation outputs. This is not repeated foundation qualification. Independently review full-catalog relevance judgments before retrieval and extraction gold before model inference. Initial gold preserved, adjudications prospective. No sealed content.

Retrieval arms: foundation full-question hybrid searches; same plus accepted seed1701API-reference probe; same plus seed1702probe. A probe is unique API-reference texts in source occurrence order joined by spaces, prefixed Formly; no spelling correction, no inferred API, no version/adapter/value/registration/model-key filtering. Perderivedquestion always run full original question hybrid top8. If nonempty APIprobe, run hybrid top8 for it, combine with original through existing reciprocal_rank_fusion top8. Merge derived-question lists by existing merge_obligations top8. No link expansion, new reranker or DB writes. Sole difference is optional query generation. Rank displacement is possible and must be measured; fullquestion survives even when a resulting top8fact is displaced. Baseline has fewer queries; report actual query counts/cost, not equal-compute superiority. Supplemental query contains no advice or authority claim. Native malformed/overlapping annotations use frozen fail-open integration behavior.

Before outputs, reviewers enumerate all directly relevant IDs and acceptable substitute groups where necessary from the46fact catalog. Measure per-request relevance precision@8, gold recall@8, nDCG@8(binaryrelevance), anyhit/MRR and complete required-group coverage. Also report top4 and perbatch. Emptygold cases are unsupported-in-catalog, not proven false in Formly: report returned candidates as unsupported retrieval exposure, never answer hallucination or false evidence-acceptance. No negative abstention logic or answerer added. A retrieval bridge is useful only if BOTH model arms improve mean supported recall@8 by>=0.02, neither loses complete-support cases or increases unsupported result count, and mean relevantprecision@8 is not lower. Report all gains/losses; no seed selection or tuning after run. Failure doesn't imply impossible future benefit.

Annotation consistency: annotate every derived question in all36fresh requests before GLiNER inference; roles per frozen six-label contract and existing integration adjudication. Record genuineambiguities explicitly before inference; do not hide them or force labels after outputs. Model settings unchanged. Measure accepted and raw exact typed precision/recall/F1, exact sets, errors perbatch and role. Target90%precision; user permits0.50–0.75percentagepoint tolerance, use minimum89.25%for each seed in EACH of3batches, plus pooled>=89.25%; report90%target separately. Better than90.75%is welcome, not failure. Keep recall>=80%perbatch, no runtime failures or core plan changes. Report count sensitivity and Wilson95%intervals: these small synthetic batches can establish observed consistency only, not population guarantees. Repeated identical deterministic inference is not independent evidence; use disjoint source batches, not repeated cached scores. Previous89.53/90.59results remain historical and are not regraded.

If frozen models fall short, diagnose exact failure categories and propose the smallest evidence-backed next candidate. Do not start training or generic regex repairs simply to chase the aggregate. User's priority is move toward useful retrieval; determine whether improving annotations would matter before training. If needed, an oracle-probe diagnostic using pre-frozen gold APImentions may be run and labeled diagnostic (not model performance); it uses identical engine/fusion/budget to reveal query-bridge ceiling.
