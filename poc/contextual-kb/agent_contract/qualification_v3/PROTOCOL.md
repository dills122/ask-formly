# Fixed qualification 3 protocol

Scope: only qualification_v3, new contract candidate and fixed transport. Existing candidates, A, v2, both extractor baselines, knowledge/data/DB and downstream unchanged. Sealed evaluation stays sealed (hash bytes only). This is synthetic development qualification, not held-out evaluation or a causal baseline comparison.

48 fresh requests in six groups of eight, repeated three times (144 fresh slots): 1 discovery/custom types/wrappers/use; 2 versions/adapters/unknown/corrected scope; 3 states/events/defaults/model-control; 4 expressions/dependencies/validation/observation; 5 support/conditions/independence/shared context; 6 mixed/literals/quoted claims/out-of-scope. Include simple and compound requests, not only prior failure shapes. Two authors independently create source/rubric pairs with scope, applicable source conditions and forbidden interpretations. Parent reviews every pair before freezing; no hidden criteria after freeze. Six separate prior diagnostics K19,K23,K46,V04,V24,N21 each repeat three times (18 slots). Total 162 slots, seven batches x three isolated native generations. Diagnostic criteria retained from the previously frozen qualifications, including the settled POLICY. Do not rewrite old grades.

Delivery: each generator reads only its packet, writes one first response list as a Python literal expression to its assigned .literal file, with no imports/code execution. Parent invokes fixed runner.py once per saved literal. ast.literal_eval does not execute generated code. Fixed standard JSON serialization without question/schema/semantic checking or filtering; exclusive output creation. Save original literal and any failure logs. No repair, resampling, retries, semantic validation before save or replacement outputs. Malformed/missing/identity-mismatched whole packet fails every scheduled slot, no salvage. Correctly saved literal/JSON remain frozen. Internal contract audit before first submission is allowed; no external feedback. Parent-generated transport invocations are identical except paths. No generation until implementation/preflight review and all input freezes complete.

Gate fixed before generation: zero observed material intent failures; fresh structure 144/144; fresh joint >=137/144; all-three joint >=44/48; every fresh group >=22/24; fresh question-meaning stability >=44/48; all 18 diagnostic slots joint. Joint = structural + semantic (including normalized globals) + correct complete mandatory bindings. Report text, semantic, ledger, structural separately and strict perfect gate. These engineering thresholds are not statistical bounds. A gate failure stops this experiment without tuning. Passing means experimental foundation eligibility only, not promotion/integration/production.

Material intent failure = lost ask, wrong polarity/value/API/scope, invented capability/constraint/app investigation, misleading assertion, or wrong mandatory gating that changes requested information. Ledger-only omission with meaning still present is a binding/joint defect, not necessarily a material intent failure. Missing/malformed slots are unassessable for intent, not observed intent failures; keep all denominators and mark unassessable. Do not interpret zero observed errors as proof of all-slot fidelity.

One stability unit = one source and all three scheduled first outputs. Meaning stability requires three structurally valid outputs with equivalent information, mandatory conditions, polarity/literals and normalized scope under POLICY; wording, decomposition, optional shared context and same-capability caveats may vary. Missing/unjudgeable triplets are unstable. Stable wrongness is possible and still fails correctness gates. Mandatory ledger stability is separate, ignoring harmless optional excerpt/segmentation variation. Exact JSON equality reported separately.

Independent implementation/preflight review before any generation, full-results fresh-context review after all generations. Max three review instances total for this authorized flow, third only for material fixes before freeze where feasible; never replace unfavorable qualification results. Review source/rubric/output for every slot; 162 semantic rows and 54 stability rows. Preserve code/input/round/literal/raw/final hashes and prior protected manifests. Tests must exercise actual absolute-path CLI from unrelated CWD, duplicate output rejection, literal parsing and semantic noninterference, not only prompt selection. No deployed API reliability, final-answer, retrieval, cost/latency or universal compatibility claims. Native revision/temp/seed uncontrolled; synthetic authors and correlated repeats limit generalization.

Fixed execution procedure: parent calls frozen qualification_v2/execution.py once with three arguments: packet JSON path, saved literal path, and a new attempt directory. The directory is exclusively reserved before launch. first-save.json records source/packet/runner hashes before fixed runner execution; completion/stdout/stderr and raw output are retained inside it. Existing attempt directory prevents retries even after parse failure. Parent after-save accounting uses execution.account to reject malformed envelopes, duplicate keys, wrong IDs/count/order as whole packets. Completion must report success and unchanged source, receipt must match frozen packet/runner/source and current raw output; otherwise all slots fail. Independently audit literal equality to raw, no producer execution. Missing artifacts stay missing. This is fixed before generation, not a change to scoring thresholds.

Post-save use execution.load_attempt, which verifies receipt/current source/packet/runner/output hashes and successful completion before calling account. Integrity failures invalidate the whole packet automatically. Local freezes are independently verified as well.

Transport reuse: invoke frozen qualification_v2/execution.py and runner.py directly, with new qualification_v3 packet/literal/attempt paths. Use that same frozen load_attempt for post-save accounting. Do not copy or modify transport. New behavior is prompt-only linked follow-up scope; structural validator remains frozen. Ledger rules must distinguish referential follow-ups from independent/general questions and optional same-field context. Read source/rubric with that distinction before freezing.
