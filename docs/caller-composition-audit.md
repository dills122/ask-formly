# Fresh caller composition audit

**2026-10-28 — diagnostic audit, no product intervention.** Ruflo coordinated
independent question generation, frozen caller execution, answer grading and a
recipe-design review. Facts, installed DB, isolated Material/reset candidate and
caller guidance were unchanged.

## Design

A fresh-context generator wrote eight questions without reading facts, repository
docs, previous questions/results or library tool evidence. Domains were repeated
structures, configuration reuse, cross-field validation, select identity, schema
customization, lifecycle ownership, custom controls and project-specific
permissions. Three questions require missing project context. These are fresh
compositions, not proof that their underlying topics have never been tested.

The question texts, request-derived decision checklists, composition rubric,
prompts, protocol and runner were frozen before execution. Callers receive only their
question and the existing generic tool-use instructions, with eight non-help and
two help calls available. No expected IDs, recipe or rubric is supplied. Each uses
a fresh ephemeral CLI session outside the repository and the current guidance14
runtime with the unchanged 192-fact DB. MCP handshake/help verifies
`formly-model-free-discovery-14+2ca5c504bc81`.

The rubric distinguishes supported mechanisms, bounded application proposals,
justified missing-context boundaries, unsupported guarantees and omissions. It
does not demand a prewritten recipe or executed application test for a clearly
labeled design proposal. Independent grading inspects actual returned facts and
final answers. Missing context is not automatically an answer failure.

## Answer findings

Independent grading found **8/8 complete bounded answers**, with all **31 requested
decisions semantically addressed**. No unsupported guarantee, demonstrated
avoidable abstention or proven retrieval defect was identified. Complete bounded
means useful supported advice with appropriate proposals and limitations, not
fully executable code or application qualification. This result does not establish
that every answer can be composed from the current facts.

This contradicts the stronger hypothesis that callers generally refuse to compose
unless a whole recipe exists. It does not prove the current instructions never
cause over-abstention. The instruction review found recovery more explicit than
composition, but that asymmetry alone is not evidence for a product change.

Two interpretation decisions are retained alongside initial tentative concerns.
C03's group/change proposal addresses rechecking without proving all Angular
scheduling transitions; the rubric never required execution or a particular leaf
subscription recipe. C06 identifies missing application code/runtime traces and
specifies diagnostic logs, satisfying the original question without a literal
imperative request. Its more targeted code request is an improvement opportunity,
not a required wording test. Frozen criteria and answers were unchanged.

The earlier timing/reset/patchValue grades remain untouched. These are different
questions with an explicitly composition-aware rubric; do not present 8/8 as a
measured improvement over earlier percentages. In particular, C03's error-routing
and message proposal is enough for this bounded design answer while its exact
Material markup and dependency scheduling caveats remain explicit.

## What to pursue

Do not broadly rewrite caller guidance or add stored recipes to make these cases
pass. Preserve positive composition patterns and target observable friction:

1. Investigate dependency evidence access for distinctions such as group
   revalidation and disabled-control serialization, with exact version scope.
   C08's project save path still needs inspection even with Angular evidence.
2. Diagnose the expensive recovery in C03 (five discoveries, eight non-help calls)
   and C02/C07 before changing ranking or guidance. Call cost alone is not a
   demonstrated retrieval bug; some questions require more evidence.
3. If a specific guidance change is justified, freeze a guidance-only comparison
   on additional fresh question families and independent generations. Keep
   facts unchanged and preserve both useful composition and justified boundaries.

This audit changes the priority from a presumed general synthesis fix to measured
dependency-evidence and recovery work. Reusable recipes remain worthwhile curated
artifacts, with the deferred construction/storage contract below; they are not
needed for every question to receive useful advice.

## Execution and preservation

All eight callers produced answers within budget. They made 12 help calls,
40 non-help calls and 19 discovery calls. Across discovery results, 41 candidate
occurrences repeated IDs from earlier discovery calls; there were no repeated
full-fact fetches. Responses totaled 729,375 reserialized envelope bytes, not
wire/token/billing cost. No tool errors or observed tool-boundary violations
occurred in the successful sessions. Tool isolation is procedural and trace-audited,
not a claim that other client tools were technically removed.

Eight initial sandbox launches failed before producing events/answers because the
CLI could not access local state. All failures are retained; the unchanged tests
were released for execution with the required permissions. There were 16 launch
attempts and eight answer-quality observations. No answer was regenerated because
of its quality.

All 103 protected files, including the actual installed DB and isolated candidate,
and all 25 reused runtime-stage files remained unchanged. The protocol and 114
raw output files are hash-frozen. Questions, prompts, complete arguments/responses,
readable per-case journeys, grades and receipts live under ignored
`test-output/composition-audit-v1/`. Historical questions and grades were not
replaced. No sealed evaluation was opened.

## Interpretation limits

This is one generation per question against one unchanged runtime. It measures
observed behavior; it cannot establish stable whole-library accuracy, causal
benefit from guidance, cross-model behavior, or browser/application correctness.
The actual caller model is unobserved unless emitted by the CLI; no model override
was supplied. No new guidance intervention was tested.

The [recipe construction contract](recipe-construction.md) separately records
step-level support, assumptions, revisions and execution evidence. It remains
deferred; this audit does not add recipe storage or automatically save answers.

Documentation/provenance validation passes. The required full maintenance command
cannot complete because the worktree compiler environment is absent; this is not
installed or model-backed runtime qualification.
