# Independent fresh author notes

Authored 22 October 2026 from the narrow mention contract and its structural validator. The author did not read existing question sets, gold annotations, training data, model results, or extraction/training implementation. Required repository and POC guidance were read. Coordination with the implementation author covered only file schemas and reserved custom registration vocabulary, never questions or gold.

`fresh.json` contains 40 source questions in eight families of five, mapped by question ID in `families.json`. Six questions have an unambiguously empty annotation set. There are 106 mentions: 46 API references, 12 registration names, nine model keys, 23 values, six versions and ten adapters. Questions ask about Formly behavior; they do not assert that a hypothetical API or custom registration exists in the library. Source strings preserve repeated occurrences, syntax quotes, Markdown backticks and opaque expressions. Offsets are exact Python codepoint half-open intervals. The pilot contract validator passed every envelope.

`probe_candidates.json` is **standalone supplied-candidate audit data only**. It must never become candidate input to the operational extractor. Its 106 valid probes are the exact gold occurrence spans, including their occurrence-specific roles. Its 50 invalid probes consist of ten merged API/value spans, ten clipped maximal APIs, ten quote-boundary errors, ten nested fragments six ordinary-prose candidates in the clear-empty cases, and four supplementary mid-identifier transport probes. `no_entity` means that the complete supplied span is not a valid independent annotation under this contract. It does not mean that nothing valid exists inside that span or that the source question is empty.

All malformed probes were checked against their complete source context. Merges join distinct roles; clipped paths omit required maximal syntax; quote probes omit a string delimiter or include a Markdown delimiter; nested fragments lie inside a maximal API or opaque value. Punctuation-bearing code fragments can comprise several lexical pieces without whitespace. Prose candidates contain multiple words. One initial mid-identifier clipping was replaced before review with a natural path-prefix clipping; this was a source-boundary quality decision, made without inspecting tokenization or model behavior. The audit does not promise that every character boundary is representable by a model. Unsupported alignment must remain visible in audit results rather than being repaired, skipped, or scored as success.

These cases are independently authored fresh evaluation material, not a claim that every lexical item is unseen during training. Common library names and APIs necessarily recur. Reserved custom names were communicated to the training author to prevent accidental custom-vocabulary overlap: lagoon-input, cedar-shell, verify-comet, silver-extension and orchid-input.

Independent prefreeze review found all 40 gold envelopes and the initial 152 probes semantically correct. At reviewer and parent request, four real source substrings clipped inside identifiers were then added as a separate bounded transport-capability subgroup, without replacing any of the original 40 malformed probes. These supplemental character offsets may be unsupported by native token-span transport; a missing score is not semantic rejection. Independent reviewer native_attribute_review approved all four supplemental source slices and semantic invalidity; freeze approved. Final structural validation passed all 40 envelopes and 156 probes. No inference results have been consulted and no experimental outcome is claimed here.
