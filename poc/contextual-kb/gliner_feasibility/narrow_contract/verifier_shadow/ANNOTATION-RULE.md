# Shadow annotation rule v1 — author proposal, pending independent review

Offsets are exact Python Unicode code points, half-open. All six roles and maximal-path/opaque-value/quote rules in the frozen narrow contract remain in force. This document proposes an adjudication for this separately versioned diagnostic only; no frozen labels or contracts are edited.

A bare ambiguous word (type, key, model, wrappers, expressions) is an API reference only when the sentence denotes the configuration member: explicit API/property/configuration wording, code notation, assignment, configuration shorthand (`type 'x'`, `key 'x'`), or direct discussion of named members together (expressions reading options.formState and updating model). Formatting alone does not override a semantic literal or opaque expression.

A type that is registered, named, called, or described as a reusable component is a category of component. Even `registered type 'x'`, selecting a named type, or a type surrounding another component does not separately mention the property `type`. The name remains registration_name. In contrast `type is 'x'`, `type: 'x'`, and bare configuration shorthand `use type 'x'` explicitly denote the member. This distinction applies equally to training and development.

The phrase `model key` or `model path` names an address concept; its supplied address is model_key, and the constituent prose words are not separately APIs. Bare `key 'x'` or `configured key` refers to the configuration member. `model value`, `a model`, and data-model discussion are prose; `model property`, API model, and coordinated named-member manipulation are APIs. Wrappers as decorators/components and expressions as generic behavior are prose; wrappers array/configuration, expressions property, and explicit comparisons with named API members are property references. Quoted behavioral claims do not become values; requested literal text does.

Unknown but explicitly presented API names remain API references. Quotes in names/keys/values are retained; Markdown backticks excluded. A complete opaque expression is one value: nested paths are not standalone mentions. Maximal paths likewise suppress inner fragments. Repeated mentions have separate coordinates. No application inspection, inferred APIs, or behavioral correctness claims are used.

Training is SUPPLIED-OCCURRENCE supervision. The training audit records every whole-word type/key/model/wrappers/expressions occurrence, including inside paths, quotes, and prose, but does not create supervision for unannotated text. Corrections change only explicitly supplied occurrences. All other frozen training labels remain outside this bounded adjudication. Full original-development inventories are reviewed separately; all 30 rows are retained. Proposed corrected dev rows and overlays are exposed diagnostic data, not a retrospective replacement for the frozen 71-positive result.

New development questions have exhaustive six-role gold inventories. Probes include every gold span, 12 declared semantic negatives (whole generic prose words; two per family) and separate exact malformed-boundary probes. Semantic negatives apply only to declared offsets, never globally to a spelling. New text must avoid unresolved role ambiguity; genuine disputes stop freeze and require review. Author receipt is not independent readiness approval.
