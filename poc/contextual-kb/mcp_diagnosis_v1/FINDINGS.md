## What the DB actually contains

Inspected all46facts (claims, context, conditions, limits and stored source quotes), all9document records and all20evidence records. All document versions are6.3.12. Only two evidence records contain explanatory bodies; the other18 are provenance metadata/links, not copied source text. No validator or props.required configuration text is stored. The incidental mentions of validation concern model/control state, inherited-type examples or visibility—not validator/message setup.

Links to pinned source files such as fieldconfig.ts may lead to additional relevant source, but those bodies are not in these stored records or returned packets. The frozen real-agent test forbids browsing/external knowledge as substitute evidence. This is a stored-knowledge diagnosis, not a statement that Formly lacks the capabilities, nor a new external source audit.

## Agent-use finding and interpretation of the prior score

No clear agent-only failure explains these six outcomes: the caller uses the relevant retrieved wrapper facts, reports missing per-field syntax, and avoids inventing validator/version7 answers. It could sometimes mention more peripheral context, but the missing primary answers are not present in its corresponding packet. The API comparison provides a positive control for actual callback-fact use.

The prior30/30usable result counted correct partial answers and honest gaps. It established integration behavior and evidence discipline, not full knowledge coverage. The4/10complete count combines coverage limits, a demonstrated retrieval miss, and deliberate out-of-scope cases. Report these separately going forward.
