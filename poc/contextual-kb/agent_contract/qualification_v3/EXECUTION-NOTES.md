# Execution provenance

Twenty-one scheduled generation contexts each supplied one saved literal response. The parent invoked the unchanged qualification2 execution CLI once per saved literal, using new qualification3 attempt directories. All executions returned zero; all first-save receipts, original literals and serialized outputs remain retained. No generated response was overwritten, corrected, discarded or resampled. No semantic feedback was sent to generators.

Two initial input-read calls were denied by a PreToolUse hook before execution: batch3/run1 and batch4/run2. The hook reported a consecutive-read limit and counter reset. Each worker reported that no input content had been read and no response had been generated; the parent confirmed that its assigned literal file did not exist. The parent resumed that same worker, with the same assigned packet and context, solely to reissue the blocked initial read and complete its first submission. No replacement worker, new semantic context, prior-output inspection or response retry was involved. These were tool-access recoveries before generation, not additional answer attempts or reruns of failed serialization. The frozen protocol and grading criteria did not change.

The saved artifacts support one first literal and one transport execution per scheduled batch. They do not independently prove unseen internal execution history, generation settings or exact chronology. Native revision, temperature and seed remain uncontrolled. Review must keep these limits visible rather than claim adversarially immutable or production-grade execution.
