The semantic rubric was written to `rubric.json` before drafting the request strings in `cases.json`. This records intended meaning, attachment of conditions, literal/API relationships, scope, and unjustified expansions; it is not an answer key for Formly behavior.

Sources read for scope: `poc/contextual-kb/AGENTS.md`, `poc/contextual-kb/STEERING.md`, and `agent_contract/refinement_v2/CONTRACT.md`. No prior cases, outputs, sealed evaluation, v3 contract/implementation, knowledge database, model weights, or web sources were consulted.

Grade semantic coverage and faithful constraints, not canonical wording or arbitrary question counts. Independently searchable outcomes should remain distinguishable; explicit comparisons should retain their paired alternatives. Exact tokens mean supplied API/literal spellings and their meaningful pairings, not mandatory quotation punctuation. Allow natural-language equivalents for code literals only when the identity/value remains unequivocal; do not silently rename supplied APIs. Each question must be independently interpretable. Reasons must justify the lookup without giving library advice.

Potential interpretation boundaries are documented per case. S04 deliberately asks for a new integration, so implementation/registration/use dependencies are justified. S16 is an uncorrected contradiction, not a correction; it must remain a neutral comparison. S17 has one unresolved pronoun beside a clear lookup. S23 retains explicit version uncertainty.
