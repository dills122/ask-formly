# Frozen qualification delivery incident

Two first executions failed before serialization: batch 5 run 1 and run 2. Both generated producer scripts used Path(__file__).resolve().parents[3], which resolves to contextual-kb for files under agent_contract/qualification_v1/test-output. The first appended refinement_v11 there; the second tried importing refinement_v11 from there. Both therefore missed the frozen module under agent_contract/refinement_v11. Run 3 used the supplied absolute module directory and delivered normally.

This is a producer harness import-path defect, not evidence that the corresponding question plans had incorrect meaning. The first literal objects are retained in the producer artifacts, but were not executed again, serialized after the failure, or salvaged into primary scoring. Tracebacks occupy the corresponding raw artifact paths. Per the protocol, all 16 affected slots fail structural/joint qualification and their eight triplets fail assessable stability. The gate therefore fails even if every delivered question plan were semantically correct.

The experiment design asked blind generation workers to construct the execution wrapper as well as the answer object. That introduced avoidable transport variability. For a future separately frozen run, prepare and test a common parent-owned runner before generation; workers should supply only first literal/structured objects to that fixed transport. This is a proposed harness improvement, not a repair applied to this qualification or a reason to change its denominators. Do not tune the question contract on the basis of this import error.
